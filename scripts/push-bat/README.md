# push-bat — ЗАЛИВКА.bat: механизм заливки локальной работы в репо

> Windows-батник + патчи как транспорт. Дополняет [PUSH.md](../../PUSH.md):
> токен живёт на машине владельца (Git Credential Manager), агентская среда
> остаётся без кредов. Один факт — одно место: этот каталог — единственная
> версия механизма.

## Зачем

Локальные клоны (машина владельца) и GitHub расходяются тремя способами:
отстали от origin; есть незапушенные коммиты; есть несохранённая работа в
рабочем дереве. Батник закрывает все три в один проход и отдельно лечит
болезнь Windows-клонов — фантомные CRLF-диффы (тысячи «изменённых» файлов,
среди которых ноль реальных правок).

## Режимы

| Режим     | Что делает                                                                                           | Когда                                             |
| --------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `sync`    | `pull --rebase` + отчёт «кто где»                                                                    | рутина, раз в день                                |
| `patch`   | незапушенные коммиты → `format-patch`, несохранённое → `00-worktree.patch`, всё в `<репо>\_patches\` | перенос работы без токена, архив, передача агенту |
| `fixcrlf` | `git add --renormalize` + честный вердикт: фантомы или реальное; фантомы откатывает                  | перед любым коммитом на Windows                   |
| `push`    | renormalize → коммит реального → `pull --rebase` → `push`                                            | заливка локальной работы в GitHub                 |
| `force`   | `push --force-with-lease`                                                                            | только осознанно; lease не убьёт чужую работу     |

Без аргументов — меню. Журнал каждого прогона: `_zalivka_log.txt` рядом
с батником.

## Установка

1. Скопировать каталог на машину владельца (например `C:	ools\push-bat\`).
2. `repos.txt.example` → `repos.txt`, вписать абсолютные пути к клонам
   (по одному в строке, `#` — комментарий).
3. Один раз: `git config --global credential.helper manager` (Git для Windows
   ставит GCM по умолчанию) — токен вводится в браузере один раз и живёт
   только на машине владельца.

## Гарантии и границы

- Батник не хранит и не печатает токены; авторизация — GCM/OAuth.
- Force по умолчанию выключен; `force-with-lease` не перезаписывает работу,
  запушенную после последней подтяжки.
- `renormalize` перед коммитом: в репо не попадают пустые CRLF-коммиты.
- Что НЕ делает: не разрешает конфликты rebase (останавливается и зовёт
  человека), не трогает untracked-файлы в patch-режиме (список — в журнале).

## Происхождение

Развёрнуто 2026-11-06 из аудита архива локальных клонов владельца
(10 репо): 0 незапушенных коммитов, 0 реальных несохранённых правок,
1971 «изменённый» файл — на 100% фантомы CRLF. Механизм существует,
чтобы следующий такой аудит занимал один прогон, а не вскрытие.

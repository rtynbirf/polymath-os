# SINGULYAR — Emergent Intent Runtime (EIR) v0.3.0

Исполняемый исследовательский прототип: **сохранить намерение человека при смене способа исполнения и не объявлять задачу выполненной без подтверждённого конечного состояния.** Продолжение v0.2 (не переписывание), с аудитом отчёта Polymath OS и RUNBOOK.

> «Эмерджентность» здесь — **проверяемая гипотеза**, а не результат. Что именно доказано и что нет — `docs/LIMITATIONS.md`, как это можно опровергнуть — `docs/EXPERIMENT_PLAN.md`.

## Запуск (Python 3.10+, без зависимостей)
```bash
python scripts/check.py        # тесты, демо, компиляция, отчёты, контрольные суммы
python src/demo.py             # failover, сбой после эффекта, честный UNKNOWN
python experiments/ablation.py # перегенерировать результаты абляции и данные для страницы
```
Откройте `prototype/index.html` — воспроизведение реальных журналов ядра по 14 сценариям сбоев (без сервера).

## Главное в одной таблице (из `EXPERIMENT_RESULTS.md`)
Лестница добавляет по одному звену: политика → контракт/failover → проверка конечного состояния → write-ahead/readback (ядро). Каждое звено убирает свой класс отказов на сценариях автора; тест `test_each_ablation_link_is_load_bearing` проверяет, что каждое звено действительно несущее. Цена: в двух сценариях ядро честно отвечает UNKNOWN вместо «наверное получилось».

## Чего здесь нет
Сети, WebRTC, шифрования, учётных записей, платежей, ИИ-моделей, мульти-писателя, внешнего аудита, доказательства новизны. Полный список — `docs/LIMITATIONS.md`.

# План эксперимента: как можно опровергнуть гипотезу «эмерджентности»

## Гипотеза (опровержимая форма)
При неизменном наборе базовых инструментов связка **контракт задачи + проверка конечного состояния + журнал write-ahead + восстановление по readback** снижает долю небезопасных исходов (ложный успех, дубликат эффекта, нарушение ограничения) по сравнению с конфигурацией без этой связки, не снижая долю корректно завершённых задач сверх заранее заданного порога.

## Что уже есть (честно)
`experiments/ablation.py` — 14 синтетических сценариев, 5 исполнителей (лестница B0…EIR). Результат в `EXPERIMENT_RESULTS.md`. Это **демонстрация механизма**: каждое звено устраняет конкретный класс отказов на сценариях, которые написал автор системы. Это не проверка гипотезы.

## Почему недостаточно
1. Сценарии написаны автором (подгонка неизбежна, пусть и бессознательная).
2. Детерминированный мир: нет шума, редких гонок, частичных сбоев сети.
3. Базовые линии намеренно просты.
4. Нет сравнения с реальными движками надёжного исполнения (Temporal и аналоги).
5. «Эмерджентность» требует эффекта, которого нет у частей по отдельности: нужен тест на **взаимодействие** звеньев (факторный дизайн), а не только лестница.

## Протокол (требуется выполнить)
1. **Предварительная регистрация:** метрики, пороги, сценарии, анализ — зафиксировать (коммит с хэшем) до запуска.
2. **Факторный дизайн 2⁴:** четыре звена (L1 политика, L2 контракт/failover, L3 проверка, L4 readback) включаются/выключаются во всех 16 комбинациях. Эмерджентность в узком смысле = значимое **взаимодействие** (эффект комбинации больше суммы эффектов звеньев). Для этого базовые исполнители должны быть выражены флагами одного ядра, а не отдельным кодом (задача фазы 5).
3. **Независимый набор сценариев:** часть пишет третья сторона; часть отложена (hold-out) и не видна при разработке.
4. **Недетерминированные сбои:** fuzz по точкам отказа (до/после каждой записи), случайные задержки, повторы сообщений, частичные ответы; ≥ N=200 прогонов на комбинацию, фиксировать seed.
5. **Метрики по отдельности (не один балл):** ложный успех; дубликаты; нарушенные ограничения; доля корректного завершения; доля честного UNKNOWN; задержка; стоимость; сложность сопровождения (строки/зависимости).
6. **Порог практической значимости** задаётся заранее (напр., снижение небезопасных исходов ≥ X при падении завершаемости ≤ Y).
7. **Сравнение с внешней системой** (Temporal или эквивалент) на тех же сценариях.
8. **Публикация всех неудач.** Если эффект не воспроизводится или объясняется одним звеном — гипотезу «эмерджентности» отвергнуть, оставив инженерную пользу отдельных звеньев.

## Критерии отказа от гипотезы
- Взаимодействие не значимо (эффекты аддитивны).
- Выигрыш исчезает на hold-out сценариях.
- Рост нарушений ограничений или стоимости выше порога.
- Простой движок исполнения даёт тот же результат дешевле.

# RTYNBIRF — Agent Execution Pack

**Версия пакета:** 0.1.0-draft  
**Дата:** 2026-11-10  
**Предлагаемое размещение:** `rtynbirf/polymath-os`  
**Статус:** подготовлен локально; в GitHub не отправлен.  
**Назначение:** дать любому совместимому coding/research agent единый, проверяемый контракт работы с задачами, кодом, тестами, доказательствами и изменениями.

> Это пакет управления исполнением агентов и документация для внедрения. Это НЕ работающий мультиагентный runtime и НЕ доказательство, что агенты уже запущены.

## Что внутри

- `AGENTS.md` — краткая точка входа для coding agents. Не энциклопедия.
- `docs/` — нормативный для этого проекта комплект: архитектура, роли, workflow, task contract, evidence, безопасность, тестирование, cross-repo rules, roadmap, runbook, источники.
- `schemas/` — JSON Schema для задач, агентов, запусков, утверждений и evidence.
- `templates/` — формы задач, решений, находок и pull request.
- `tasks/` — четыре готовых discovery-задачи первой волны для параллельного исполнения.
- `examples/` — пример задачи и пример цепочки доказательств.
- `tools/validate_pack.py` — локальная проверка схем, ссылок и обязательных файлов без запуска кода репозитория.
- `tools/publish-to-github.ps1` — неразрушающий Windows-публикатор: проверяет origin/права/конфликты, создаёт ветку, запускает проверки, делает push и открывает PR через локальную авторизацию `gh`.
- `tests/` — тесты валидатора пакета.
- `.github/ISSUE_TEMPLATE/agent-task.yml` — форма задачи для GitHub Issues.
- `.github/pull_request_template.md` — шаблон PR.

## Установка без перезаписи

Поскольку текущее дерево `polymath-os` и наличие существующего `AGENTS.md` не были проверены, пакет намеренно не содержит автоматического перезаписывания файлов.

1. Сначала клонируй репозиторий через GitHub CLI:

```powershell
gh auth login --web
gh repo clone rtynbirf/polymath-os
cd polymath-os
```

2. Распакуй пакет отдельно и сравни его содержимое с текущим репозиторием.
3. Запусти `tools/publish-to-github.ps1` с параметром `-RepoPath`. Скрипт проверяет конфликты и прекращает работу, если существующий файл отличается.
4. Если конфликтует существующий `AGENTS.md`, объедини правила вручную; не заменяй файл целиком.
5. Скрипт создаёт отдельную ветку, запускает проверки, выполняет push и открывает PR. Основная ветка не изменяется напрямую.

**Авторизация:** скрипт не принимает PAT в аргументах и не записывает credentials в файлы. Используй локальную авторизацию `gh auth login --web`; GitHub CLI сам управляет сессией. Не вставляй токены в исходники, логи или коммиты. Если PAT уже опубликован в открытом виде, проверь его состояние и при необходимости отзови/замени через GitHub Settings → Developer settings → Personal access tokens.

## Проверка самого пакета

Требуется Python 3.10+:

```bash
python tools/validate_pack.py
python -m unittest discover -s tests -v
```

Для проверки соответствия примеров JSON Schema установи `jsonschema` (если пакет ещё не установлен): `python -m pip install "jsonschema>=4.20,<5"`.

Эти команды проверяют документационный пакет и его схемы. Они НЕ проверяют сборку, тесты или корректность `polymath-os`.

## Правила статуса

- `UNKNOWN` — нет проверяемых данных.
- `DECLARED` — только написано в документации или сообщено участником.
- `OBSERVED` — непосредственно найдено в коде, конфигурации или записи.
- `EXECUTED` — команда реально выполнена; сохранены commit, среда и код возврата.
- `INDEPENDENTLY_VERIFIED` — другой исполнитель независимо воспроизвёл проверку.

Заявление агента о выполнении не является доказательством выполнения.

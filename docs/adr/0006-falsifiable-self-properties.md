# ADR-0006: Falsifiable self-* properties — каждое заявление с отрицательным тестом

**Date:** 2026-10-16
**Status:** Accepted
**Deciders:** @USER
**Audit:** A5 (Шесть self-* — заявления, не измерения)

## Context

Polymath OS отчёт заявлял 6 эмерджентных свойств: self-audit, self-publish, self-bootstrap, self-evidence, self-verify, self-rollback. Все 6 — **декларации**, не измерения. Наличие CI не доказывает, что система проверяет сама себя; наличие документации не доказывает соответствие реальному состоянию.

Каждое «self-*» должно быть переформулировано до **гарантии, которую можно опровергнуть**.

## Decision

Каждое self-* свойство переформулировано с тремя колонками:

| Заявление | Что реально гарантирует | Свидетельство, которое требуется |

### Self-audit
- **Что гарантирует:** CI проверяет то, что в него **явно включили** как test/lint/check.
- **Свидетельство:** карта рисков → проверки; **отрицательный тест** (внесённый дефект должен краснить CI). Мутационный контроль для критичных путей.

### Self-publish
- **Что гарантирует:** деплой по правилам (allowlist публикаций + проверка итогового состава).
- **Свидетельство:** список проверок + **отрицательный тест** (заметка без `publish: true` с «ловушкой-строкой» не должна появиться в собранном сайте).

### Self-bootstrap
- **Что гарантирует:** скрипт запускается на **чистой** машине.
- **Свидетельство:** запуск на чистой VM (через `act` или Codespaces), запись времени и версий. Quarterly: bootstrap-test.

### Self-evidence
- **Что гарантирует:** документы лежат в git (это **тривиально**).
- **Свидетельство нетривиальное:** трассировка «утверждение → тест/запуск». Документы не подтверждают друг друга по кругу. Каждое архитектурное утверждение в ADR имеет ссылку на тест или runbook-процедуру.

### Self-verify
- **Что гарантирует:** подпись артефакта проверена в deploy.
- **Свидетельство:** `cosign verify` + `cosign verify-attestation` на deploy-шаге. **Отрицательный тест:** артефакт без подписи **не должен деплоиться** (CI fail).

### Self-rollback
- **Что гарантирует:** откат выполнен (см. ADR-0005 — три раздельные цели).
- **Свидетельство:** учение + проверка состояния после отката (метрика ошибок возвращается к фону).

## Consequences

- **Positive:**
  - Свойства перестают быть слоганами. Каждое — конкретный тест или drill.
  - При изменении системы свойство либо остаётся зелёным (тест проходит), либо явно ломается (test fails) — это сигнал, что что-то в архитектуре изменилось.
  - Мутационный контроль (mutation testing) ловит тесты, которые «зелёные, но ничего не проверяют». Реальный пример: после 35 зелёных тестов SINGULYAR подмена INCONCLUSIVE→CONFIRMED их не провалила → тест добавлен только после мутации (см. `runtime/docs/AUDIT_POLYMATH.md` §A10).
- **Negative:**
  - Накладные расходы: mutation testing медленный (10-100× unit tests).
  - Не для каждого свойства есть falsifiable witness (например, "self-evidence" слабее других).
- **Neutral:**
  - RUNBOOK и TZ обновлены с explicit свидетелями для каждого self-*.

## Alternatives Considered

### Оставить 6 self-* как декларации
Отвергнуто: A5 прямо указал — это заявления, не измерения.

### Убрать self-* как hype
Отвергнуто: свойства осмысленные, проблема только в проверяемости. Falsify, не отменяй.

### Мутационный контроль на каждый PR
Отвергнуто: слишком дорого. Только для критичных путей (auth, secrets handling, recovery).

# ADR-0003: Exit gates вместо календарной длины фаз

**Date:** 2026-10-16
**Status:** Accepted
**Deciders:** @USER
**Audit:** A2 (арифметика roadmap)

## Context

ROADMAP.md заявлял «4 фазы × ~22 дня», но фактическая таблица дней: 7 / 14 / 39 / 30 (Phase 0: 1-7, Phase 1: 8-21, Phase 2: 22-60, Phase 3: 61-90). Несоответствие:
- Phase 0 = 7 дней, не 22
- Phase 2 = 39 дней, почти вдвое больше «~22»

Календарные обещания создают ложное ощущение управления: фаза может «закончиться» по календарю, но не быть готовой по фактам.

## Decision

Перейти от **календарной длины** к **exit gates** — каждая фаза имеет явное условие выхода, а не дату окончания. Длительности — ориентиры (`~`), не обязательство.

### Структура фазы

```
Фаза: <name>
Ориентир длительности: ~N дней (не обязательство)
Цель: <что должно быть достижимо>
─── Exit Gates (ВСЕ должны быть зелёные) ───
- Gate 1: <verifiable condition>
- Gate 2: <verifiable condition>
...
─── Anti-gates (что НЕ должно быть) ───
- <known failure mode>
```

### Критерий перехода

Фаза закрыта, когда **все exit gates зелёные** и **все anti-gates подтверждены отсутствующими**. Если по календарю прошёл ~N дней, но gates красные — фаза продолжается. Если gates зелёные раньше — фаза закрыта раньше.

## Consequences

- **Positive:**
  - Roadmap перестаёт врать. Календарный план отделён от фактической готовности.
  - Gates уже implicitly были в отчёте — теперь они explicit и primary.
  - Легче понять где застряли: какой gate красный.
- **Negative:**
  - Нет «даты релиза» для внешних стейкхолдеров. Решение: confidence intervals («v1.0.0 в Q4 2026 ± 30 дней»).
  - Команда может застрять на фазе, если gate зависит от внешнего фактора (vendor).
- **Neutral:**
  - Длительность по-прежнему полезна как **ориентир для оценки бюджета**, но не как promise.

## Alternatives Considered

### Честные длительности фаз (переименовать «~22» в реальные)
Отвергнуто: всё равно календарь. Любой calendar-based план страдает от одной проблемы — фаза закончилась по календарю, но не готова.

### Без roadmap (only exit gates)
Отвергнуто: roadmap нужен для budgeting и onboarding. Gates без фаз слишком атомарны.
